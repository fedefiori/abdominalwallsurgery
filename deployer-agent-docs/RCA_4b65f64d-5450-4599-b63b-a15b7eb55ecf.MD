# RCA — Build failure (run 4b65f64d-5450-4599-b63b-a15b7eb55ecf)

## Summary
Initial deploy of `chirurgia-test` (template: fastapi_react_mongo_shadcn, cloudflare frontend) failed at the **build_image** step, inside the Docker `frontend-build` stage during `yarn build`. Root cause is in the app's own source: `frontend/craco.config.js` reads a **backend** directory at build time, and that directory is not present in the frontend build context.

## Exact error (Cloud Build, step #2 docker-build, frontend-build 13/14)
```
Error: ENOENT: no such file or directory, scandir '/app/backend/data/pages'
    at Object.readdirSync (node:fs:1631:26)
    at Object.<anonymous> (/app/craco.config.js:233:4)
Node.js v24.20.0
error Command failed with exit code 1.
```
The generic `retry_with_backoff ... yarn install && yarn build` wrapper around it is just the retry harness — the real failure is the ENOENT above.

## Root cause
`frontend/craco.config.js` (~line 231) executes at module-load time (evaluated during `yarn build`):
```js
const fs = require("fs");
const PAGE_PATHS = fs
  .readdirSync("/app/backend/data/pages")
  .filter((f) => f.endsWith(".json"))
  .map((f) => "/" + f.replace(".json", ""))
  .concat(["/home"]);
```
- In **preview**, `/app/backend/` and `/app/frontend/` sit side by side, so `/app/backend/data/pages` exists (confirmed: it contains `home.json`, `contatti.json`, etc.) and the config loads fine.
- In the **Docker `frontend-build` stage**, only `frontend/` is COPYed into `/app` (correct, standard behaviour). `/app/backend/data/pages` therefore does not exist → `readdirSync` throws ENOENT → craco config load fails → `yarn build` exits 1 → build step fails.

`PAGE_PATHS` is used only for the dev-server `slash-301` middleware (preview-only; the comment notes production redirects are handled by the Cloudflare Worker via `/api/seo/routes`). So the directory read is unnecessary for the production build and must not hard-crash it.

This is **not** a deployment-manifest bug — the manifest copies `frontend/` correctly. The fix is in app source and is owned by E1.

## Fix (source — `frontend/craco.config.js`)
Guard the read so a missing directory degrades gracefully instead of throwing. Replace the block at ~line 230-235:
```js
const fs = require("fs");
let PAGE_PATHS = [];
try {
  PAGE_PATHS = fs
    .readdirSync("/app/backend/data/pages")
    .filter((f) => f.endsWith(".json"))
    .map((f) => "/" + f.replace(".json", ""));
} catch (e) {
  if (e.code !== "ENOENT") throw e; // dir absent at build time (frontend-only build context) — preview-only middleware
}
PAGE_PATHS = PAGE_PATHS.concat(["/home"]);
```
Optionally resolve the path relative to the project instead of hard-coding `/app/backend/...`, but the try/catch alone unblocks the build.

## Verification (eph sandbox, source at /app/scratch)
- Reproduced: `fs.readdirSync('<missing>/backend/data/pages')` → `REPRO ENOENT: ENOENT` (matches the build failure).
- Verified fix: the guarded version does not throw and yields `PAGE_PATHS = ["/home"]` when the dir is absent, and would still enumerate pages normally when present.
- Note: a full `yarn build` was not run end-to-end in-pod; the fix targets the exact throwing line and the mechanism is confirmed.
